# Perbaikan: struk 58mm terpotong di kanan (clip oleh modal)

## Status

Putaran 1 (selesai, ter-ship): lebar `.receipt-paper` 72mm → 54mm, helper `src/utils/printReceipt.js` menyuntik `@page { size: 58mm <tinggi>mm }` saat cetak struk (POS, Transaksi, Nota fotokopi), diukur dengan `offsetHeight` (kebal `scale-90`). Lint/build lulus, image frontend sudah di-rebuild.

Putaran 2 (ini): laporan user — hasil preview/cetak terpotong di kanan (`Rp 70.0|`, `INV-20261008-00|`, footer terpotong).

## Diagnosis (sudah diverifikasi, jangan diselidiki ulang)

- CSS live di `https://localhost:9999` **sudah benar**: `.receipt-paper{width:54mm}` + preflight `box-sizing:border-box`; injeksi `@page` aktif (aspect halaman screenshot ≈ 58mm × 88mm). 54mm < 58mm → tak mungkin terpotong oleh kertasnya.
- Pelakunya modal: `src/components/ui/Modal.jsx:16` card punya `backdrop-blur-glass` → **`backdrop-filter` menjadikan card containing block** untuk `#receipt-print-area` (di `@media print` elemen ini `position:absolute; left:0; top:0`). Card juga `overflow-hidden` dan overlay `fixed inset-0 p-4` (16px).
- Di print: struk dipotong tepi card ≈ 58mm − 2×16px ≈ **49,5mm < 54mm** → kolom kanan hilang 2–3 karakter (cocok persis dengan screenshot); `max-h-[92vh]` di card ikut membatasi secara vertikal.
- Sebelumnya halaman A4 (card ≈ 201mm) menutupi celah ini. Invoices/Reports sudah menghindar lewat portal ke body (komentar `src/pages/Invoices.jsx:444`); struk belum.

## Keputusan

1. **Fix**: satu aturan di `@media print` — matikan `backdrop-filter` pada card modal saat cetak. Card berhenti jadi containing block → containing block pindah ke overlay `fixed` (yang **tidak** punya `overflow`) → tak ada clip. Layar tidak tersentuh (aturan dibatasi `@media print`), blur modal tetap ada saat normal.
   - Cakup: POS, Transaksi, Nota fotokopi (satu class `.backdrop-blur-glass` dipakai semua modal).
   - Cetak invoice/laporan/label tidak terpengaruh (area cetak mereka di luar modal / di-portal, `#root` disembunyikan).
2. **Fallback bila verifikasi masih terpotong**: portal `#receipt-print-area` ke `body` saat cetak, mengikuti pola `InvoicePrint` (perubahan lebih besar — hanya jika fix CSS terbukti tidak cukup).
3. Skala dialog print harus 100% — skala >100% dari sisi user tetap akan memotong, bukan bug kode.

## Task list

1. **Repro cepat (headless, sebelum fix)** — fixture HTML di dir temp: overlay `fixed inset-0 p-4` + card `backdrop-filter:blur(24px); overflow:hidden` + `#receipt-print-area{position:absolute;left:0;top:0}` berisi `.receipt-paper{width:54mm;height:80mm}` + `@page{size:58mm 88mm;margin:0}` → `chrome --headless --print-to-pdf` → harap **terpotong** (bukti mekanisme).
2. **Fix** di `src/index.css`, di dalam blok `@media print` yang sudah ada:
   ```css
   /* Modal card: backdrop-filter membuatnya containing block untuk
      #receipt-print-area (abs) sehingga overflow-hidden memotong struk
      pada halaman 58mm. Matikan saat cetak; layar tidak terpengaruh. */
   .backdrop-blur-glass {
     backdrop-filter: none;
     -webkit-backdrop-filter: none;
   }
   ```
3. **Verifikasi ulang fixture** dengan aturan fix → halaman 58mm, konten 54mm tampil utuh, **1 halaman**.
4. `npm run lint && npm run build`.
5. `docker compose up -d --build frontend` (frontend saja; backend tak berubah).
6. Minta user hard-refresh (Cmd+Shift+R) lalu ulangi: POS → transaksi → Cetak Struk (Alt+P), skala 100%.

## Validasi

- Save as PDF → ukuran halaman 58mm × N mm.
- Vertikal: footer tidak terpotong (`max-h-[92vh]` card tak lagi membatasi karena card bukan containing block).
- Layar: preview modal struk tetap sama (blur/`max-h` modal tidak berubah di luar print).
- Regresi: cetak invoice A4, laporan bulanan, label barcode tidak berubah.

## Risiko / escalation

- Jika masih terpotong setelah fix CSS (mekanisme clip ternyata beda): naik ke fallback portal — render area struk ke `body` saat print, pola `Invoices.jsx:444`.
- Catatan ke user: pastikan skala print 100% (bukan "Fit"/custom >100).
